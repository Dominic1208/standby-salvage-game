# Game Brief: 待机回收站（Standby Salvage）

**One-sentence pitch:** 你的 AI 员工在外面替你干活，你在回收站里收破烂、砍价、还贷；员工一推门来请示，你点一下，他们的工作就不会停。

## Core loop
- 顾客上门卖货（什么都收）→ 查看线索、鉴定，留意顾客说的来历有没有矛盾
- 最多三轮砍价 → 成交或拒绝
- 日终把货卖给收购商、完成当天的订单、结算贷款
- 任何时候 AI 员工都可能进门请示、汇报或求援。处理完回到刚才那一步，什么都不丢

## Player goal & fail state — what "working" looks like
- 一局 7 天，第 3 天和第 7 天各还一期贷款，还清就算胜利；还不上，店被收走，这一局结束
- 一天营业大约 3–5 分钟。处理一条 AI 请求只需要一次进门、一张卡片、一次滑动或点击

## MVP — what must exist to be the game
1. 顾客与货物生成：什么都收，包括会污染相邻货物的问题货
2. 鉴定线索 + 简单的找谎言（每件货最多一处矛盾）
3. 三轮砍价，顾客有耐心条
4. 日终结算：收购商订单、卖货、7 天贷款
5. 无损暂停与自动存档：每个动作都存档，随时退出、随时恢复
6. 员工通讯（游戏内）：员工进门请示 → 全屏真实批准卡片；完成汇报给情报；报错求援
7. 真实链路：电脑端连接程序 + Claude Code + iPhone 锁屏推送（5 分钟和 15 分钟再提醒，永不自动批准），通过 Tailscale 连接

## Out of scope — not building this
- 接入 Codex（MVP 之后的第一件事）
- 记忆碎片和图鉴、回头客、背单词玩法
- 职业路线、制造、警察系统
- 音效和音乐、联网和账号
- iOS 原生应用、安卓 APK
- 用 Skill 换风格、换玩法（开源之前再做）

## Build order
1. **（并行）技术验证**：一条真实的 Claude Code 确认 → iPhone 锁屏推送 → 手机上批准 → 电脑继续执行。这是风险最大的部分，也是产品成立的前提
2. **（并行）一笔交易可玩**：鉴定、砍价、成交，然后导出网页，在 iPhone 上试玩
3. 把员工通讯接到真实链路上
4. 日终结算和贷款
5. 存档和恢复
6. 接入 Codex

---
**Who it's for / what they feel:** 用 AI 干活、经常离开电脑的人。几分钟一段、有点紧张但不累的小经营，同时安心：AI 不会因为等我而停下。

**Art & audio direction:** 竖屏单手，暗色调加暖色霓虹的杂货铺，扁平风格。先用色块和文字占位，以后可以用 ComfyUI 生成素材。没有音效，只用推送的系统提示音。

**Reference game:** 《深空当铺》（Probably Stolen）：只保留"鉴定、砍价、还贷"的压力循环；不做制造、职业路线和警察。

**Architecture note:** 网页外壳负责推送、连接和批准卡片，Godot 4 游戏嵌在页面里，导出网页版。批准核心固定不变，游戏层以后开源给别人魔改。

**Safety boundary:** 员工进门只是入口。真实批准一律是全屏、不套游戏皮肤的纯文字卡片（哪个 AI、哪个任务、什么命令或文件），批准用滑动、拒绝用单击；不按 AI 运行时长或批准次数发奖励。
